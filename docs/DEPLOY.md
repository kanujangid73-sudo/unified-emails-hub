# Deploying for free

| Part | Service | Free plan |
|---|---|---|
| Database | [Neon](https://neon.tech) Postgres | 0.5 GB, sleeps when idle, wakes in under a second |
| API (FastAPI + background sync) | [Render](https://render.com) web service | 512 MB RAM, sleeps after 15 minutes idle |
| Web app | Render static site | Always on, served from a CDN |
| AI (optional) | [Google Gemini](https://aistudio.google.com/apikey) | Free-tier rate limits |

Everything is described in [`render.yaml`](../render.yaml), a Render "Blueprint", so both services
are created in one step. No credit card is needed.

## 1. Database (Neon)

If you already have a Neon project (for example from another app), add a database to it instead
of creating a new project:

1. Open your project at https://console.neon.tech → **Branches → main → Databases → New database**.
   Name it `mailhub`.
2. Click **Connect**, pick the `mailhub` database and copy the connection string:
   ```
   postgresql://neondb_owner:...@ep-something.us-east-2.aws.neon.tech/mailhub?sslmode=require
   ```
   It contains the password: keep it private.

New to Neon? Sign up with GitHub, create a project in **AWS US East 2 (Ohio)** (the API runs in
Render's Ohio region, next to it), then do the two steps above. Tables are created automatically
on the API's first start.

## 2. Services (Render)

1. At https://dashboard.render.com click **New → Blueprint**.
2. Paste the repository URL `https://github.com/kanujangid73-sudo/unified-emails-hub` (or connect
   GitHub and pick it) and continue. Render reads `render.yaml` and shows two services,
   `mailhub-api` and `mailhub-web`.
3. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | The Neon connection string from step 1 |
   | `FRONTEND_URL` | `https://mailhub-web.onrender.com` |
   | `CORS_ORIGINS` | `https://mailhub-web.onrender.com` |
   | `GEMINI_API_KEY` | Your free Gemini key, or leave empty to use the built-in assistant |
   | `VITE_API_URL` | `https://mailhub-api.onrender.com` |

4. Click **Apply**. The first build takes a few minutes. `SECRET_KEY` and `ENCRYPTION_KEY` are
   generated by Render.
5. **Check the real URLs.** If a name was taken, Render adds a suffix (e.g.
   `mailhub-api-x7k2.onrender.com`). Open each service, copy its URL from the top of the page, and
   if it differs from the table:
   - in **mailhub-api → Environment**, fix `FRONTEND_URL` and `CORS_ORIGINS`;
   - in **mailhub-web → Environment**, fix `VITE_API_URL`, then **Manual Deploy → Deploy latest
     commit** (the web app reads it at build time).

## 3. Check it works

1. Open `https://<api>/api/health`: you should see `{"status":"ok",...}`.
2. Open the web app and press **Try the demo**. The first visit after a quiet spell can take up to
   a minute while the free API wakes up; the sign-in page says so.
3. If the API doesn't start, open its **Logs**. A line starting with `Invalid production
   settings` names the missing variable.

## 4. Optional extras

- **Keep it awake.** Add a free https://uptimerobot.com monitor for `https://<api>/api/health`
  every 5 minutes. The health check doesn't touch the database, so Neon can still sleep.
  Render's free plan gives 750 hours a month in total across your free services, so if another
  app also stays awake all month, only keep one of them pinged.
- **Auto-deploy from GitHub.** In Render, copy each service's **Settings → Deploy Hook** URL. In
  GitHub, **Settings → Secrets and variables → Actions**, add them as `RENDER_DEPLOY_HOOK_API` and
  `RENDER_DEPLOY_HOOK_WEB`. After that, every push to `main` that passes the tests redeploys the
  parts that changed. Treat hook URLs like passwords.
- **Real mailboxes.** Add the redirect URIs `https://<api>/api/oauth/gmail/callback` and
  `.../outlook/callback` in Google Cloud and Microsoft Entra, then set `GOOGLE_CLIENT_ID`,
  `GOOGLE_CLIENT_SECRET`, `MICROSOFT_CLIENT_ID` and `MICROSOFT_CLIENT_SECRET` on `mailhub-api`. See
  [CONNECT_ACCOUNTS.md](CONNECT_ACCOUNTS.md). IMAP accounts need nothing extra.

## Good to know

- **Keys.** Never replace `ENCRYPTION_KEY`; saved mailbox sign-ins would become unreadable. To
  rotate it, set `ENCRYPTION_KEY=<new>,<old>`.
- **Background sync** runs inside the API process, so it pauses while the free service sleeps
  and catches up (incrementally) when it wakes.
- **Demo accounts** are deleted after 24 hours by an hourly clean-up, so the free database
  doesn't fill up.
- **One instance is enough**, but more would also work: the scheduler claims accounts with a
  database lease, so two instances never sync the same mailbox at once.
- **Other hosts.** `backend/Dockerfile` runs anywhere that sets `$PORT` (Koyeb, Railway, Fly.io,
  a VPS) with the same variables; the web app is a static build for Vercel, Netlify or
  Cloudflare Pages with `VITE_API_URL` set.
